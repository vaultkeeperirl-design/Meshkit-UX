# Forge's Journal - Critical Learnings

- **Platform-specific build failures:** Windows paths use backslashes instead of forward slashes, which might cause shell scripting differences (sh vs pwsh) in GitHub Actions when building release artifacts. Ensuring we use cross-platform compatible CLI commands or use built-in Action functionality prevents path separation issues on Windows.
- **Cache restoration/invalidation:** Node and Python package caching behaves differently. In GitHub Actions, utilizing `actions/setup-node` with `cache: 'npm'` and `actions/setup-python` with `cache: 'pip'` allows for efficient caching while making sure we check package lockfiles or requirements txt files to detect any invalidation without downloading dependencies every time from scratch.
- **Cache restoration/invalidation bug:** Surprising behavior in cache restoration: `hashFiles` on `backend/tools/llama.cpp/**` was evaluating to an empty hash because the directory was not cloned until after the cache step. Moved the clone step before the cache step.
- **Empty directory cloning bug:** When checking for the existence of a directory before running `git clone` in CI scripts (e.g., `if [ ! -d "dir" ]`), the directory may already exist but be empty (e.g. from an empty git submodule or aborted clone). This causes the clone step to skip, leading to failures later. Using `if [ ! -d "dir" ] || [ -z "$(ls -A dir 2>/dev/null)" ]; then rm -rf dir && git clone ...; fi` prevents fatal exit code 128 errors.
- **Dependency conflicts across OS environments:** Installing Python dependencies for vendored tools (`llama.cpp` and `mergekit`) in the wrong order causes pip dependency resolution conflicts (e.g., `llama.cpp` downgrades `click` to 8.1.8, breaking `mergekit` which requires `click==8.2.1`). The installation order should be `llama.cpp` then `mergekit` to ensure the final environment satisfies the primary tool's requirements.
- **Platform-specific build failures (Electron-builder icons):** Building Electron apps on Windows (`electron-builder`) fails with `ERR_ELECTRON_BUILDER_CANNOT_EXECUTE` when using `.svg` icons in the `win` or `linux` targets because the Windows icon conversion tool fails to parse them. Use `.ico` or `.png` files, or remove the explicit icon definition to use the default.
- **Platform-specific build failures (PyInstaller add-data):** On Windows, PyInstaller requires the `--add-data` flag paths to be separated by a semicolon (`;`), while Unix systems use a colon (`:`). Hardcoding a colon causes a build failure on Windows runners where PyInstaller will parse the path incorrectly. Always use `os.pathsep` (e.g., `f'--add-data=tools{os.pathsep}tools'`) to ensure cross-platform compatibility.
- **Platform-specific build failures (Bash PYTHONPATH on Windows):** In GitHub Actions on Windows runners using `bash`, avoid `$(pwd)` for environment variables or paths passed to native Windows tools like Python (e.g., `export PYTHONPATH="$(pwd)"`). The Git Bash shell evaluates `$(pwd)` to a Unix-style path (e.g., `/d/a/...`) that the Windows Python interpreter cannot parse, leading to `ModuleNotFoundError`. Instead, use cross-platform compatible relative paths like `.`.
